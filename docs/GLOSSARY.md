# Glossary — Folder File Control (code identity: `WindowsFileManager`)

> Domain terms, abbreviations, and coined names used across the codebase, kept alphabetical.
> Terms marked **(coined)** are this product's own vocabulary and will not be found in external
> documentation. Where a term maps to a type, the type and its file are named.
> Narrative background for these terms is in [CONTEXT.md](CONTEXT.md); per-feature behavior
> contracts are in [specs/](specs/).

| Term | Definition |
|------|------------|
| **Action history** | The undo stack: up to 30 `ActionHistoryEntry` records (`src/WindowsFileManager.Core/Models/ActionHistoryEntry.cs`), newest first, persisted with the settings and surfaced in the History tab. Each entry carries an `ActionHistoryKind` — `MoveFiles`, `RecycleFiles`, `RecycleDirectories`, or `CreateShortcuts` — and only the collection matching that kind is meaningful (`ItemCount` switches on `Kind`). Undo replays the inverse; moves are unwound in reverse order so conflict-renames resolve correctly. Empty-directory removal during **Flatten** is *not* recorded and is therefore not undoable. |
| **Analytics** | **Local, in-memory scan statistics — not telemetry.** `ScanAnalytics.FromResult(ScanResult)` (`src/WindowsFileManager.Core/Models/ScanAnalytics.cs`) computes unique-file count, duplicate percentage, wasted percentage, the top 8 duplicated extensions, and a fixed six-bucket size distribution, rendered in a side panel. Nothing is sent anywhere; the app makes no network calls. |
| **AnyCPU** | The only platform the solution defines. `WindowsFileManager.sln` declares exactly two configurations — `Debug|Any CPU` and `Release|Any CPU` — and every project maps `Any CPU → Any CPU`; there is no x86 or x64 solution platform and no `PlatformTarget` in any `.csproj`. The x64 story appears only at publish/package time: `RuntimeIdentifiers=win-x64` in `src/WindowsFileManager/WindowsFileManager.csproj`, `RUNTIME_ID: win-x64` in `.github/workflows/msix-pipeline.yml`, and `ProcessorArchitecture="x64"` in `Package.appxmanifest`. |
| **Base filters** *(coined — UI label)* | The default duplicate-scan toolbar (include-subdirectories, exclude folders, target paths). It is **mutually exclusive** with the **match-by-name-regex** toolbar: `DuplicateMatchByRegex` shows one and hides the other via visibility converters in `Views/MainWindow.xaml`. |
| **Check-Coverage.ps1** | The coverage gate: `scripts/Check-Coverage.ps1`. It reads a Cobertura report (`-ReportPath`, or the most recently written `tests/**/TestResults/**/coverage.cobertura.xml`), prints a per-module line/branch/method table, and exits 1 when any total falls below `-Threshold` (default 100). Cobertura carries no method rate, so the script derives one — a method counts as covered when it has at least one covered line, which is what coverlet's own method threshold measured. It also fails a report containing no `<package>` elements, because that means instrumentation was lost rather than tests missing. Run it **after** `dotnet test --collect:"XPlat Code Coverage"`; both workflows run it as a step of its own under `shell: pwsh`. See ADR-011. |
| **Clean Architecture** | The four-project layering this repo uses: **Core** (models + interfaces, no dependencies) ← **Application** (business services, depends only on Core interfaces) and ← **Infrastructure** (real I/O implementations); **UI** (WPF) depends on all three. Dependency flow: `UI → Application → Core ← Infrastructure`. The point is that all business logic can be unit-tested against a mocked `IFileSystemService` without touching a disk. See ADR-001 in [adr/README.md](adr/README.md). |
| **Clear Subfolders** *(coined — product feature)* | The bulk-sprawl action: after a folder search, discover every distinct subfolder *name* across the selected result folders (with an occurrence count and its parent locations), then recycle that subfolder inside **every** selected root in one confirmed operation. Implemented as `ScanSubfolders` / `ClearSelectedSubfolders` in `src/WindowsFileManager/ViewModels/MainViewModel.cs`; see [specs/SPEC-008-clear-subfolders.md](specs/SPEC-008-clear-subfolders.md). |
| **Content hash** | The identity of a file's *bytes*, independent of its name, path, or timestamps. Two files with the same content hash are treated as duplicates. Here the content hash is an uppercase-hex **SHA256** digest produced by `FileHashService.ComputeHash` (`src/WindowsFileManager.Application/Services/FileHashService.cs`) by streaming the whole file. Contrast with **match-by-name regex mode**, which never reads content. |
| **coverlet** | The .NET coverage tool this project measures with. Only **`coverlet.collector` 6.0.2** is referenced (in `tests/WindowsFileManager.Tests/WindowsFileManager.Tests.csproj`); it is the `XPlat Code Coverage` data collector, so coverage is produced by `dotnet test --collect:"XPlat Code Coverage" --settings tests/WindowsFileManager.Tests/coverlet.runsettings` and written as Cobertura under `tests/**/TestResults/<guid>/coverage.cobertura.xml`. That runsettings file is the **single source of coverage scope** (`Include` / `Exclude` / `ExcludeByFile` / `ExcludeByAttribute`) and is read on every run, local and CI. **The collector cannot enforce a threshold** — that is **Check-Coverage.ps1**'s job (see its entry above). `coverlet.msbuild`, and the `CollectCoverage` / `Threshold` / `ThresholdType` property block that made a bare `dotnet test` fail below 100%, were removed on 2026-09-02 because build-time instrumentation raced; `-p:CollectCoverage=false` is now a no-op property that skips nothing. See ADR-011 (which supersedes ADR-005). |
| **Duplicate group** | A set of 2+ files sharing a grouping key, plus the metadata the UI renders: `DuplicateGroup` (`src/WindowsFileManager.Core/Models/DuplicateGroup.cs`) with `Hash`, `FileSize`, `Files` (sorted by path), and computed `Count`, `WastedBytes`, `FileExtension`, and display strings. Never produced with fewer than two members. Groups are returned sorted by `WastedBytes` descending. |
| **Exclude folder** | A folder **name** (not a path) that the scanner skips entirely during enumeration — the classic entries are `node_modules`, `.git`, `obj`, `bin`. Held as `ToggleItem`s in the UI and as `ScanOptions.ExcludeFolderNames` in the service, compared `OrdinalIgnoreCase`. Because it is applied while walking, it makes scans faster as well as smaller. Note: exclusions are only honored on the recursive enumeration path — with *Include Subdirectories* off there are no subfolders to exclude. |
| **Extension filter** | A **post-scan view filter**, not a scan parameter: `ExtensionFilter` items (`src/WindowsFileManager/ViewModels/ExtensionFilter.cs`) are built from the results, one per extension present, each with a checkbox, file count, and total size; unchecking one hides those groups without rescanning. Files with no extension are grouped under `(no ext)`. Distinct from `ScanOptions.FileExtensions`, the service-level allow-list. |
| **Filter rule** | A user-authored selection rule: `FilterRule` (`src/WindowsFileManager.Core/Models/FilterRule.cs`) with `Pattern`, `IsEnabled`, `IsRegex`, `IgnoreCase`, `Action`, and `Target`. **Rules drive selection, not visibility.** Applying rules walks each file through the list in priority order and the **first enabled matching rule wins**: `FilterAction.Include` (ordinal 0) *checks* the file, `FilterAction.Exclude` (ordinal 1) *unchecks* it. `FilterTarget` chooses what the pattern is matched against — `Filename` (0) or `Filepath` (1). Regex evaluation carries a 1-second match timeout and any failure is treated as "no match". **Vocabulary warning:** the older UI names for these actions were *Contains* (select) and *Ignore* (deselect) — that wording still appears in `README.md`, in `CLAUDE.md`'s note about renaming `FilterAction.Select` → `Contains`, and in a stale XML doc comment on `FilterRule.Action`. The enum members in code today are `Include` / `Exclude`; the ordinals never changed, which is what keeps old `settings.json` files loading. See ADR-007 and [specs/SPEC-003-custom-filter-rules.md](specs/SPEC-003-custom-filter-rules.md). |
| **Flatten** *(coined — product feature)* | A folder action that moves every nested file up into its selected root folder, resolving name collisions with ` (2)`, ` (3)` suffixes, and optionally removing the directories left empty afterwards. The moves are recorded as a `MoveFiles` history entry and are undoable; the **empty-directory removal is a permanent `Directory.Delete`, is not recorded in history, and cannot be undone**. `FlattenFolder` / `RemoveEmptyDirectoriesRecursive` in `MainViewModel.cs`. |
| **FolderMatchType** | The enum that says *how* a folder-search pattern is tested against a candidate folder: `FolderMatchType` in `src/WindowsFileManager.Core/Models/FolderSearchPattern.cs`. It has **six** members — `Include` (0), `Match` (1), `Contains` (2), `Exclude` (3), `Mismatch` (4), `NotContain` (5) — whose ordinals are pinned by a test because they are serialized as integers. Exact semantics for each value are in the [FolderMatchType values](#foldermatchtype-values) section below. The in-app **MATCH TYPES** help popup (`Views/MainWindow.xaml`) still documents only five of them — it omits `NotContain`, which was added 2026-04-23 and is fully implemented and exposed in the UI. |
| **Folder search pattern** | One rule in a folder search: `FolderSearchPattern` (`src/WindowsFileManager.Core/Models/FolderSearchPattern.cs`) pairing a text `Pattern` with a `MatchType` (default `Match`), plus `IsEnabled` and a display-only `Priority`. **All enabled patterns must pass (AND logic)** for a folder to be a result, and **zero enabled patterns means every folder matches**. See [specs/SPEC-007-folder-search.md](specs/SPEC-007-folder-search.md). |
| **IFileSystemService** | The single I/O seam, declared in `src/WindowsFileManager.Core/Services/IFileSystemService.cs` with eleven members: `EnumerateFiles`, `EnumerateDirectories`, `GetFileSize`, `GetLastWriteTime`, `OpenRead`, `DirectoryExists`, `FileExists`, `GetFileName`, `ReadAllText`, `WriteAllText`, `CreateDirectory`. Application services take it by constructor injection so tests can supply a Moq double; the real implementation is `WindowsFileManager.Infrastructure.Services.FileSystemService`, which is deliberately excluded from coverage because it *is* the untestable boundary. See ADR-004. Note that some UI-layer folder operations call `System.IO` directly rather than going through this interface. |
| **Info card** *(coined — internal `PreviewType` value)* | The preview fallback for files WPF cannot render inline (documents, archives, fonts, executables, databases, 3-D models, and images WPF cannot decode): an emoji glyph plus a type label instead of content. Produced by `SetInfoCardPreview` in `MainViewModel.cs`. The other preview types are `image`, `video`, `audio`, `text`, `unsupported`, and `none`. |
| **Keeper** *(coined)* | The copy of a duplicate group that is deliberately **left unselected** and therefore survives the action. Nothing in the data model marks a keeper — it is emergent: *Select Newer* leaves the oldest file by `LastModified` unselected, *Select Older* leaves the newest, and *Select All* leaves none. There is no invariant forcing a group to retain one member; "Delete All in group" removes every copy after confirmation. Reversibility (Recycle Bin + action history), not prevention, is the safety model. |
| **Link sibling folders** *(coined — product feature)* | A folder action that creates `.lnk` shortcuts between sibling folders sharing a parent, depth-capped by a layer setting and optionally name-prefixed. Shortcuts are written by `Helpers/ShortcutHelper.CreateFolderShortcut` via late-bound `WScript.Shell` COM, and recorded as a `CreateShortcuts` history entry (undo deletes the shortcuts). Existing shortcuts are skipped. |
| **Match-by-name regex mode** | The alternative duplicate-detection mode: instead of size + content hash, a user regex is matched against the **file name only**, and the concatenated capture groups (or the whole match when the pattern has no groups) become the grouping key. Implemented as `GroupByNameRegex` in `DuplicateScannerService.cs`. **Size and content are never consulted**, so grouped files are not necessarily byte-identical. Keys are compared case-sensitively (use an inline `(?i)` for case-insensitivity); the regex carries a 1-second match timeout, and a timeout aborts the whole scan with a descriptive `ArgumentException`. |
| **Mini preview** | The 80 px thumbnail shown beside each file in the duplicate list, produced by `Helpers/MiniPreviewConverter.cs`. Fifteen extensions WPF can decode natively load directly as a `BitmapImage`; everything else goes through a **shell thumbnail**. Results live in a `static ConcurrentDictionary` cache that is unbounded and is cleared only at the start of a scan. Toggled by `IsMiniPreview`; when no thumbnail is available the UI falls back to an emoji from `FileTypeIconConverter`. |
| **MSIX** | Microsoft's Windows app package format, and this project's Store distribution target. **The package is assembled by hand in CI**, not by a packaging project: `dotnet publish -r win-x64 --self-contained` output plus `Package.appxmanifest` (renamed to `AppxManifest.xml`) plus assets are copied into a layout folder, then `makeappx.exe pack` produces the `.msix` (`.github/workflows/msix-pipeline.yml`). The `-p:WindowsPackageType=MSIX` command appears only in `scripts/New-DevCertificate.ps1` (line 50, in its printed "Next steps"); it is not the CI path, and `CLAUDE.md` records that the property is **inert** here — the project declares no `WindowsPackageType`, no Windows App SDK reference, and no `.wapproj`. The manifest declares the restricted capability `runFullTrust`. See ADR-008. |
| **MVVM** | Model–View–ViewModel, the WPF UI pattern used here — **hand-rolled, with no MVVM framework and no DI container**. `ViewModels/ViewModelBase.cs` supplies `INotifyPropertyChanged` plus a `SetProperty` helper; `Helpers/RelayCommand.cs` supplies `ICommand`; `MainViewModel` is instantiated **by XAML** (`<Window.DataContext><vm:MainViewModel /></Window.DataContext>`) through a parameterless constructor that builds its own services. Code-behind is used only where binding cannot reach: window geometry, `MediaElement` transport, column-header sorting, modal dialogs, and tab-driven panel state. See ADR-002. |
| **Overlapping-path deduplication** | The guarantee that adding both `D:\` and `D:\sub` as targets does not make a file appear to be its own duplicate. Enforced by a single `.Distinct(StringComparer.OrdinalIgnoreCase)` over the concatenated per-target enumerations in `DuplicateScannerService.Scan`, before any filtering or hashing. |
| **Priority** | Rule ordering. Both `FilterRule` and `FolderSearchPattern` expose an `int Priority` where **1 is highest**, recomputed from list position whenever rules are added or reordered (`RefreshRulePriorities`, `Priority = index + 1`). For filter rules the priority decides which rule wins (first enabled match); for folder-search patterns it is display/reorder only, since all enabled patterns must pass anyway. Priority is marked `[JsonIgnore]` on both models — it is derived from list order, not persisted. |
| **Profile** | A named, switchable bundle of the entire workflow configuration: `ProfileSettings` (`src/WindowsFileManager.Core/Models/ProfileSettings.cs`, 22 properties — target paths and their disabled set, exclude folders, filter rules, folder-search patterns, sort option, preview/playback preferences, regex-match state, search depth, and more). `AppSettings` holds the profile list plus `ActiveProfileName`. Switching snapshots the live state into the outgoing profile and applies the incoming one; cloning deep-copies rules and patterns. **Window geometry and action history are global, not per-profile.** |
| **Recycle** | The project's standard delete: `Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile` / `DeleteDirectory` with `RecycleOption.SendToRecycleBin` (`RecycleFile` / `RecycleDirectory` in `MainViewModel.cs`). This is the main safety net — recycled items are recoverable both from Explorer and through the app's undo, which drives the Windows Shell `Restore` verb. Per-item shell confirmations are suppressed (`UIOption.OnlyErrorDialogs`); the app's own `MessageBox` is the confirmation. |
| **RelayCommand** | The hand-rolled `ICommand` used by every button and menu item (`src/WindowsFileManager/Helpers/RelayCommand.cs`): an `Action<object?>` with an optional `Predicate<object?>` for `CanExecute`. `CanExecuteChanged` forwards to `CommandManager.RequerySuggested`, so re-evaluation is driven by WPF's requery cycle rather than by explicit view-model notifications. |
| **SARIF** | *Static Analysis Results Interchange Format* — the JSON schema GitHub's code-scanning UI consumes. The MSIX pipeline runs Semgrep with `--sarif --output semgrep-results.sarif` and uploads the file via `github/codeql-action/upload-sarif@v3`, which is why the workflow requests `security-events: write` permission. |
| **Semgrep** | The SAST scanner in the MSIX pipeline (`security-scan` job, `ubuntu-latest`, `semgrep/semgrep` container), run with `--config p/default --config p/csharp --error`. `--error` makes any finding a non-zero exit, and because the packaging job declares `needs: security-scan`, a finding blocks the build. |
| **settings.json** | The one persistence artifact: `%APPDATA%\WindowsFileManager\settings.json`, a `System.Text.Json` serialization of `AppSettings` written with `WriteIndented = true` by `SettingsService` (`src/WindowsFileManager.Application/Services/SettingsService.cs`). Rewritten **on every mutation**, not on window close (see ADR-006). It contains absolute scanned paths, move-target paths, folder names, regex patterns, and the action history — plaintext, readable and writable by any process running as the user. Loading tolerates corruption at two levels — the two `catch (JsonException)` blocks in `SettingsService` (whole-file deserialize → return defaults; legacy-schema migration → keep defaults); there is no per-element tolerance. It migrates the pre-profile flat schema into a single "Default" profile. |
| **SHA256** | The 256-bit cryptographic hash used as the duplicate identity. Chosen for collision resistance, not speed — a false positive here means deleting a file that was not actually a duplicate. Computed with `System.Security.Cryptography.SHA256.HashData(stream)` over the whole file and formatted as uppercase hex by `Convert.ToHexString`. There is no size cap and no chunk-sampling shortcut: every candidate file is read end to end. |
| **Shell thumbnail** | A preview image produced by the Windows Shell rather than by the app, used for file types WPF cannot decode. `MiniPreviewConverter` P/Invokes `SHCreateItemFromParsingName` to get an `IShellItem`, casts it to `IShellItemImageFactory`, and calls `GetImage(80×80)`. This runs third-party shell extension code **in-process**; both P/Invokes carry `[DefaultDllImportSearchPaths(DllImportSearchPath.System32)]` to prevent DLL planting, and GDI/COM handles are released in `finally` blocks. |
| **Size grouping** | Stage 2 of the duplicate scan and the reason scanning is fast: byte-identical files must have identical lengths, so grouping by `FileSize` and discarding every size-group with fewer than two members eliminates most files using metadata only — before any file content is read. Only the survivors are hashed. |
| **StyleCop** | `StyleCop.Analyzers` 1.1.118, referenced with `PrivateAssets=all` in `Directory.Build.props` so it applies to **every** project including tests. Configured by `stylecop.json` (public and interface members must carry XML documentation, `System` usings first, usings outside the namespace, newline at end of file). Fourteen rules are explicitly suppressed in `.editorconfig`, each with a rationale comment. Combined with `TreatWarningsAsErrors`, a StyleCop finding is a build failure. See ADR-009. |
| **Subfolder item** | The paging/selection model behind the Clear-Subfolders list: `SubfolderItem` (`src/WindowsFileManager.Core/Models/SubfolderItem.cs`) holding a subfolder `Name`, an occurrence `Count`, a `TotalSize`, and the `SubfolderLocation` list of parents it appears under. It paginates its own locations at a fixed `PageSize = 50` with a location filter (setting the filter resets to page 0) — the model, not the view, owns paging. |
| **Target path** | A folder the user adds to be scanned or searched. Stored as a `ToggleItem` so it can be disabled without being removed; only enabled entries reach `ScanOptions.TargetPaths`. Added by browse dialog or by typing — the typed path is taken verbatim, with no existence check or normalization. |
| **ToggleItem** | The tiny wrapper that gives every list entry an on/off checkbox: `src/WindowsFileManager/ViewModels/ToggleItem.cs`, a `ViewModelBase` with an immutable `string Value` and a notifying `bool IsEnabled` (default `true`). Used for **target paths** and **exclude folders** so a user can park an entry temporarily instead of deleting and retyping it. Marked `[ExcludeFromCodeCoverage]`. |
| **TreatWarningsAsErrors** | The build gate set in `Directory.Build.props` (`TreatWarningsAsErrors=true` plus `CodeAnalysisTreatWarningsAsErrors=true`, `EnableNETAnalyzers`, `AnalysisLevel=latest`, `EnforceCodeStyleInBuild`). Every Roslyn, code-style, and StyleCop warning is a compile error in every project. Enabled 2026-04-16. See ADR-009. |
| **WACK** | *Windows App Certification Kit* — Microsoft's Store-submission validator. The `wack-validation` CI job downloads the built `.msix` and runs `appcert.exe test -appxpackagepath …`, publishing `wack-report.xml` as an artifact. A failing certification test fails the job. |
| **Wasted space** | The headline metric: the bytes you would reclaim by keeping exactly one copy. Per group, `WastedBytes = sum(file sizes) − max(file size)` — three 1 MB copies waste 2 MB, not 3 MB. A fallback branch, `FileSize × (Count − 1)`, covers groups whose individual sizes are all zero. `ScanResult.TotalWastedBytes` sums it across groups, and groups are sorted by it descending so the biggest win is first. |

## FolderMatchType values

Every comparison is on `Path.GetFileName(candidateFolder)` using `OrdinalIgnoreCase`. Evaluated in
`SearchFoldersRecursive` (`src/WindowsFileManager/ViewModels/MainViewModel.cs`); an unrecognized
value returns `false`. All **enabled** patterns must pass for the folder to be a result.

| Value | Ordinal | Passes when | Typical use |
|-------|---------|-------------|-------------|
| `Include` | 0 | The folder **name contains** the pattern (substring). | `Include` + `client` → `client-api`, `old-client` |
| `Match` | 1 | The folder **name equals** the pattern exactly. | `Match` + `src` → only folders literally named `src` |
| `Contains` | 2 | The folder **holds a matching immediate child**. A pattern starting `*.` is a wildcard extension match over the folder's files; any other pattern is an exact-name existence check that accepts **either a child directory or a child file**. Immediate children only — no recursion. | `Contains` + `.git` → repository roots; `Contains` + `*.sln` → solution folders |
| `Exclude` | 3 | The folder **name does not contain** the pattern — the negation of `Include`. | `Exclude` + `test` → skip anything with "test" in the name |
| `Mismatch` | 4 | The folder **name does not equal** the pattern — the negation of `Match`. | `Mismatch` + `node_modules` |
| `NotContain` | 5 | The folder **does not hold a matching immediate child** — the negation of `Contains`. Added 2026-04-23, after the in-app **MATCH TYPES** help popup was written; that popup still omits it. | `NotContain` + `package.json` → project folders that are not Node packages |

Child-existence lookups (`Contains` / `NotContain`) use `System.IO.Directory` and `System.IO.File`
directly rather than `IFileSystemService`, and swallow every exception as `false` — an
unreadable folder is treated as "does not contain".
