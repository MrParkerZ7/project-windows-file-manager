## Concept

The terminal node of the epic. G-001 is not done until the documentation reflects what it shipped - this is the
mechanism that stops an epic going stale the moment it lands. Every task in the epic carries its own same-commit spec
obligation; T-014 reconciles the doc *set*, which no individual task can see.

## Design

Run `perfect-docs --auto-approve` scoped to the surfaces this epic touched. It is deliberately the last node: it runs
only after every implementation leaf is done, so it documents reality rather than intent.

## Detail

Reconcile, at minimum:

- **`ARCHITECTURE.md`** - the module blurb and namespace/folder table gain `Themes/`; the "Change X, touch Y" table
  gains a row for changing a colour, radius or type token.
- **`docs/modules/ui.md`** - the file tree gains `Themes/`; the help-markup colour table is re-derived from resources
  rather than literals; the section-Testing "never start an `Application`" invariant is rewritten if T-002 shipped
  `XamlLoadTests`.
- **`docs/specs/`** - SPEC-004, SPEC-005, SPEC-006, SPEC-007, SPEC-009 and SPEC-010 must all be current, and
  `_index.md` must list SPEC-011 if T-011 created it.
- **`docs/adr/README.md`, `docs/README.md`** - ADR-012's register rows.
- **`CHANGELOG.md`** - the epic's user-visible changes under `[Unreleased]`.
- **The stale test counts** - multiple documents state "217 tests"; the figure will have moved again.

## Interfaces / contracts

Consumes the finished state of every other task. Publishes nothing. Nothing may list T-014 as a predecessor - that
would be a cycle.

## Acceptance criteria + Case-Coverage Matrix

- [ ] Every doc layer this epic touched ends `current` under `perfect-docs`.
- [ ] No document still describes the pre-3a shell.
- [ ] `docs/design/DESIGN-001` is **not** rewritten - T-013's freeze contract must hold (see Edge cases).
- [ ] No test-count figure in any document contradicts the actual suite.

| Case | Success | Fail |
|---|---|---|
| Specs (required) | all six current | one lags the shipped behaviour |
| ARCHITECTURE / module docs (required) | `Themes/` present, tables updated | stale file tree |
| ADR-012 registers (required) | all rows present | ADR unregistered |
| Frozen design record (required) | DESIGN-001 untouched | "synced" to what shipped |
| Boundary - a task shipped `amended` | the contract change is documented | silently absorbed |

## Edge cases

**The dangerous one:** `perfect-docs` reconciles documents against reality, and `docs/design/DESIGN-001` is a
*frozen* record of design-time intent that deliberately differs from what shipped (3a adopted, 4a deferred, plus any
fidelity deviations such as the per-copy path tinting T-007 declined). T-013's freeze contract must exist and be
honoured, or this task will "correct" the historical record out of existence. T-013 states this itself and is right.

## Dependencies

All fifteen preceding tasks. Two precisions from the coherence pass: T-010 is a blocker via **Stage B** specifically
(Stage A is `T-010a` and lands in Wave 0), and T-011 via **Phase 3** (T-014 needs SPEC-011 to exist and be current).

## Risks

Running before an implementation task is genuinely done produces confidently wrong documentation. The `blocked-by`
set is the mitigation - do not relax it.

## Out of scope

Writing new specs for features this epic did not touch, and any code change.
