## Why / vision

The app works and is well tested underneath, but its shell has accreted: one 2,796-line XAML file, 70 hand-typed
colours, seven separate undo buttons, 84 help popups of which at least four describe behaviour the code does not
have. Option **3a** from the redesign canvas replaces that with an IDE-standard frame - tool-windows with 30px
headers, splitters, underlined editor tabs, one toolbar row per panel, one action bar, one status bar. The user
gains a layout they already know from every IDE; the codebase gains the style layer it never had.

**Design source:** `Redesign Explorations.dc.html`, block `id="3a"` (turn 3, "IDE-standard structure (IntelliJ
conventions) in Broadsheet"). Baseline for comparison: `Baseline - Current WPF UI.dc.html`. T-013 vendors both into
`docs/design/` as frozen design-time intent.

**Explicitly deferred - option 4a is NOT in this epic.** Turn 4 layers a light/dark theme switch, colour-as-meaning
(cyan interactive/keep, magenta destructive, print-yellow attention), tinted file-type tags, tinted selected rows and
duotone panel icons *on top of* 3a. Turn 3 states plainly: *"The typography, colors and controls stay Broadsheet -
only the framing is IDE-standard."* T-001 is nevertheless required to choose `DynamicResource` vs `StaticResource`
deliberately so that a later 4a goal is not blocked by this one. The coherence pass verified no 4a leakage across all
thirteen specs.

## Honest limits

Pixel fidelity to 3a is verified by **manual screenshot only**. `coverlet.runsettings` excludes `*Views*`, and
`MainViewModel` carries `[ExcludeFromCodeCoverage]`, so every line of XAML this epic rewrites has zero automated
verification - while the eight new types it adds in `Helpers`/`ViewModels`/`Core` carry a strict 100% obligation. The
gate is strict on the code carrying almost no risk and silent on the code carrying all of it. Say so in each PR body
rather than letting green CI imply visual correctness.
