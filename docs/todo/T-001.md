## Concept

The 3a IDE frame is a *system*, not a screen: a 260/1/1fr/1/360 grid whose every tool-window header, hairline, toolbar band and action bar repeats the same handful of values. You cannot build that out of a file where 393 colour decisions are typed by hand at their point of use. T-001 is the plumbing task that makes T-002 through T-011 possible, and it is deliberately the *only* task in the epic that changes nothing you can see.

Today `src/WindowsFileManager/App.xaml` is 314 bytes with an empty `<Application.Resources>`; there is no `ResourceDictionary` anywhere in the repo. `Views/MainWindow.xaml` is 2,796 lines / 222,866 bytes carrying **364 hex-literal occurrences of 70 distinct colours** plus 15 named-brush occurrences, and it declares **78 `<Style>` blocks of which only one is keyed** — the other 77 are anonymous inline `<X.Style>` blocks, so 100 of those hex literals sit inside `<Setter Value="#…">` where nothing can reach them. `Views/ProfileNameDialog.xaml` adds 8 more hex occurrences (2 colours unique to it) and one `Brushes.IndianRed` in its code-behind; `Helpers/FormattedTextBehavior.cs` hardcodes four more `Color.FromRgb` brushes, one of which (`#FFEBEE`) exists nowhere in XAML. **393 colour sites, 76 distinct values, across four files.**

T-001 lifts all 76 into keyed resources merged at `Application.Resources` and rewrites all 393 sites to reference them. It authors, alongside, the real Broadsheet token layer read verbatim off the canvas's `_ds/broadsheet-.../styles.css` — `#f3f2f2` ground, `#eae9e9` surface, `#201e1d` ink, `#0088b0` accent, the 9-step neutral and accent ramps, the 5/10/15/20/30/40 px space scale, the 1/2/4 px radii, the 16 %-ink divider — so that T-003 onwards has somewhere to bind. Those Broadsheet values are **defined and consumed by nothing yet**: the app keeps today's Material-blue palette, byte-for-byte, because the acceptance bar is pixel-equivalence against the current build.

Two things make this the *root* task rather than a nice-to-have. First, ordering: doing the substitution now means it happens once, in one file, mechanically; doing it after T-002's decomposition means doing it across a dozen UserControls. Second, reversibility: after T-001 the entire look of the app is 76 lines in one file. T-004's "make the tab strip a 38 px underlined strip" stops being an archaeology exercise and becomes an edit.

Third — and this is what the review pass surfaced — T-001 is not only the token *store*, it is the **naming authority** for everything eight downstream tasks will bind by name. Eight tasks independently invented eight key shapes (`BsRadiusMd`, `Style.Button.Primary`, `ToolWindowHeaderStyle`, `PanelHelp.Button`, `Broadsheet.FocusVisual`, …) because T-001's published contract reserved value keys and nothing else. The revision closes that: one prefix, one reserved category set including `Broadsheet.Style.*`, one folder, one merge entry per task — and a contract test that fails the build on any deviation, so the convention is enforced rather than remembered.

What T-001 is emphatically not: it is not the 4a theme goal. It does not add a dark ramp, a `Light`/`Dark` switch, colour-as-meaning, tinted rows or tinted file-type tags. It only ensures — by choosing `DynamicResource` for every themeable value, deliberately and for a stated reason — that when that goal is picked up, the answer is "swap one merged dictionary", not "rewrite the app".

## Design

**Layering.** Three new `ResourceDictionary` files under a new `src/WindowsFileManager/Themes/` folder, merged into `App.xaml` in this order:

```
Themes/Broadsheet.Tokens.xaml    ← design-system primitives, from the canvas. Consumed by nothing in T-001.
Themes/Legacy.Palette.xaml       ← the 76 in-use colour values, verbatim. Every view binds here today.
Themes/Legacy.Metrics.xaml       ← the in-use radii, hairline thicknesses and font families.
```

Order is load-bearing: `StaticResource` resolves only backwards through merged-dictionary parse order, so any forward reference from a Legacy file into `Broadsheet.Tokens` requires Broadsheet to be merged first. (In T-001 no such reference exists — the legacy layer is deliberately self-contained — but T-003 will add them.)

**`Themes/` is the normative folder for every dictionary in the epic.** Not `Styles/`, not `Resources/`, not a per-family folder. Every `ResourceDictionary` any later task authors lands in `src/WindowsFileManager/Themes/`, and every entry in `App.xaml`'s `MergedDictionaries` has a `Source` beginning `Themes/`. A task may author as many *family* files as it likes, but it appends **exactly one** entry to `App.xaml` — an aggregator dictionary that merges its own families. Both halves are asserted by the contract test (Detail §9, assertions 7 and 10), so a task that invents a sibling folder or splices five entries into `App.xaml` fails `dotnet test`, not review.

**Why `Application.Resources` and not `Window.Resources`.** Three concrete reasons, all verified against this codebase:
1. `ProfileNameDialog` is a second `Window` (`Views/ProfileNameDialog.xaml`) with its own 8 colour sites. Window-scoped resources would need duplicating.
2. `HelpButtonStyle`'s `ControlTemplate` contains a `<Popup x:Name="HelpPopup">`. A `Popup` hosts its child in a **separate visual tree** on its own `HwndSource`; `DynamicResource` lookup walks the *logical* tree and then terminates at `Application.Resources`. Anchoring the dictionaries at App level makes every one of the 21 help popups resolve unconditionally, with no reasoning about tree position required.
3. `FormattedTextBehavior` will resolve its four brushes via `TryFindResource` on the target `TextBlock` — which is inside that popup. Same argument.

`Window.Resources` in `MainWindow.xaml` keeps exactly what it has today: the five converters and `HelpButtonStyle`. Moving those is T-003's job, not T-001's.

**The two-palette scheme, and its lifetime.** `Legacy.Palette.xaml` is a **transitional layer with a written expiry and a named owner for that expiry**, not a permanent second palette. Its keys are named for the role the colour *plays today* (observed, not invented), and each carries a provenance comment naming the Broadsheet token it is destined for:

```xml
<!-- was #1565C0 · 44 uses · primary action, link, RAM readout, help glyph
     broadsheet: Broadsheet.Brush.Accent -->
<SolidColorBrush x:Key="Legacy.Brush.Action.Primary" Color="#1565C0" po:Freeze="True" />
```

The alternative — naming keys for their *final* semantic role in 3a and flipping only values in T-003 — was rejected because it does not survive contact with the data: seven of the 76 colours (`#388E3C` green, `#6A1B9A` purple, `#E65100` orange, the `#FFF8DC`/`#DAA520`/`#B8860B` History-tab gold trio, `#E0D0A0` gold divider) have **no** Broadsheet counterpart; in 3a they collapse into accent or neutral, and collapsing them in T-001 would change pixels. Legacy keys therefore describe what *is*; Broadsheet keys describe what *will be*; the comment is the map between them. T-004 through T-011 rebind their surfaces to Broadsheet keys as they rebuild them, and **T-011 — the last task in the epic that touches a rendered surface — deletes both legacy dictionaries** (Interfaces §6). The deletion is not left to memory: contract-test assertion 9 makes the layer's liveness self-reporting, failing the build both if the dictionaries linger with zero referents and if they are deleted while referents remain. T-012's ADR records the two-phase migration as deliberate.

**`DynamicResource` vs `StaticResource` — normative rule, machine-enforced.** This is the epic's single reference convention, and it is stated as a rule with three clauses:

| Where | Which | Why |
|---|---|---|
| Every colour/brush reference **from a view** (`Views/**/*.xaml`: `Background`, `Foreground`, `BorderBrush`, `Setter.Value`, `DropShadowEffect.Color`) | **`DynamicResource`** | Runtime-resolved and re-resolved when the dictionary changes. A future theme goal swaps `App.Resources.MergedDictionaries[n]` and every one of the 379 view sites repaints in place. `StaticResource` bakes the brush into BAML at load — a swap would require tearing down and rebuilding the visual tree, which is exactly the thing that "must not be blocked". |
| Every reference **from inside a dictionary** to build another resource (a brush's `Color`, a Broadsheet brush referencing a Broadsheet color, a `Style` setter referencing a radius) | **`StaticResource`** | `DynamicResource` on a `Freezable`'s property makes the object **unfreezable**, forfeiting `po:Freeze` and adding a `ResourceReferenceExpression` per brush. A theme swap replaces the whole dictionary — colours *and* brushes *and* styles together — so intra-dictionary references never need to be live. |
| Non-themeable structure referenced from a view: `CornerRadius`, `Thickness`, `FontSize` doubles, `FontFamily`, converters, `Style` and `ControlTemplate` keys | **`StaticResource`** | These do not vary by theme; a static reference is cheaper and, critically, **fails loudly** (`XamlParseException` at load) on a typo, whereas a mistyped `DynamicResource` key silently leaves the property at its default. Use the noisier mechanism wherever liveness is not required. |

**This rule is normative for the whole epic and is enforced by contract-test assertion 8 — it is not a review item.** The reviewer's job is design intent; the test's job is the convention. The rule is decidable from XML alone: a reference's required kind follows from the *element type* of the node that declares its key in `Themes/` (`SolidColorBrush`/`Color` → `DynamicResource`; `CornerRadius`/`Thickness`/`sys:Double`/`FontFamily`/`Style`/`ControlTemplate` → `StaticResource`), and `DynamicResource` is banned outright inside `Themes/`. That last cell is the single biggest correctness hazard in this task and drives the whole verification design below.

**Freezing.** Every brush in every dictionary carries `po:Freeze="True"` (`xmlns:po="http://schemas.microsoft.com/winfx/2006/xaml/presentation/options"` + `mc:Ignorable="po"`). With 393 references to 76 brushes this is a real win, and it is safe here: `grep -c 'Storyboard\|ColorAnimation\|DoubleAnimation'` over both view files returns **0**, so no brush is ever animated.

**Verification, honestly.** There are no UI tests, the xUnit runner is **not STA** (documented in the repo's own `FormattedTextBehaviorTests.cs`: *"needs an STA apartment the xUnit runner does not provide"*), and 100 % line/branch/method is enforced on non-excluded code by `scripts/Check-Coverage.ps1`. So:
- Verification is a **new xUnit class that parses the XAML as XML** (`System.Xml.Linq`), constructs **no WPF type** and therefore needs no STA. It asserts the resource contract mechanically: every key referenced resolves, no duplicate keys, the key→value map matches a committed expectation set, no colour literal survives outside `Themes/`, **every key matches the reserved name shape, every reference uses the mandated kind, every merge entry points into `Themes/`, and the legacy layer's lifetime matches its referent count**.
- Its file discovery is **recursive** (`SearchOption.AllDirectories` over `src/WindowsFileManager/`, minus `Themes/`, `bin/`, `obj/`), so a later task that introduces `Views/Controls/` is covered the moment it lands — no per-task glob widening, and nothing silently narrows.
- It lives in the test assembly, which `coverlet.runsettings` excludes (`IncludeTestAssembly=false`), so it adds **zero** coverage burden and needs no new CI step — `dotnet test` already runs it.
- **T-001 adds no measured production code.** No converters, no attached properties, no value converters. The only production C# it touches is `Helpers/FormattedTextBehavior.cs`, which already carries `[ExcludeFromCodeCoverage]` (honoured via `ExcludeByAttribute`) and is guarded by an existing test asserting that attribute is still present — and `Views/ProfileNameDialog.xaml.cs`, whose namespace is excluded by `[WindowsFileManager]*Views*`.
- Pixel-equivalence itself is proven by a **one-shot value-preservation audit**, not a permanent harness: for every line the diff touches, the resolved token value must equal the literal it replaced. This is a mode of the same test (`-CompareRef`-style, driven off the committed expectation map) plus a manual before/after screenshot at 1600×900 recorded in the commit body. A permanent visual-regression harness is out of scope and is called out as such.

## Edge cases

**`DynamicResource` fails silently — the defining hazard.** A mistyped `{DynamicResource Legacy.Brush.Text.Secondry}` throws nothing, logs nothing, and leaves the property at its inherited/default value — on a `Foreground` that means black text where grey was intended, on a `Background` it means `null` (transparent) where white was intended. With 393 substitutions, some will be mistyped. Contract test 1 (key-resolvability) is the *only* thing standing between that and a silent regression, which is why it is specified before anything else — and it is also why assertion 8 forces `StaticResource` everywhere liveness is not needed: a static reference converts the same class of typo into a loud `XamlParseException`.

**`color-mix()` has no WPF equivalent.** Broadsheet's `--color-divider` is `color-mix(in srgb, #201e1d 16%, transparent)` and the artboard's per-copy row rule is the same at 6 %. Transcribing either as a plain opaque hex loses the compositing; transcribing it as `#29201E1D` (alpha) changes how it renders over a non-`#F3F2F2` ground. Both forms ship, both are commented with their CSS source, and T-003 picks per surface. Getting this wrong is invisible in T-001 (nothing consumes them) and expensive in T-005 where the two 1 px splitters land.

**WPF cannot express `letter-spacing`.** 3a's uppercase kicker rows (`Target folders`, `Skip folders named`, `File / copy`, `Modified`, `Size`, `Keep`) are `letter-spacing:.08em`. `TextBlock` has no such property. The token is recorded as a documented gap, not faked.

**`Setter.Value` vs `Trigger.Value`.** Both are spelled `Value=`. 100 hex literals live in `<Setter Property="…" Value="#…">`; a `Trigger`'s own `Value=` is the *comparison operand* (`True`, an enum name) and must never be rewritten. A blind sed on `Value="#` is safe today because every hex-valued `Value=` is a `Setter` — but a blind sed on `Value=` is not.

**`po:Freeze` and animation are mutually exclusive.** Frozen brushes cannot be animated. Verified safe: `grep -c 'Storyboard\|ColorAnimation\|BeginStoryboard\|DoubleAnimation'` returns 0 across both view files. If a later task adds a colour animation it must animate a *copy*, not the frozen resource.

**Merged-dictionary order is `StaticResource`'s reality.** `StaticResource` resolves only against what has already been parsed. Broadsheet must merge before anything that references it. `DynamicResource` does not care — which is a second, quieter argument for using it view-side. It is also why T-003's aggregator (Interfaces §2) is appended *after* `Broadsheet.Tokens.xaml`: an aggregator merged before its own token source resolves nothing.

**The contract test must exclude `Themes/` from its view sweep, and only `Themes/`.** Assertion 3 forbids colour literals outside `Themes/`; if the exclusion were written as a path *prefix* match it would also swallow a hypothetical `Views/Themes/` a later task might create. Match on the immediate directory segment under the project root, and let `bin/`/`obj/` out the same way. Getting this wrong makes the sweep quietly narrower than it reads — the exact failure assertion 11 exists to catch.

**A recursive sweep will find generated XAML if `bin`/`obj` are not excluded.** `obj/Debug/net8.0-windows10.0.22621.0/` holds `.g.i.cs` and, on some SDK versions, copied `.xaml` — sweeping those would produce phantom literal failures on a clean checkout that vanish after a `git clean`. Exclude both by directory segment, and prefer enumerating from the project directory rather than the repo root.

**Two `#FFFFFF` roles, one value.** `Background="White"` (10 panel fills) and `Foreground="White"` (4 on-accent labels) are the same colour serving opposite roles. They get two keys. When T-003 recolours, `Surface.Paper` becomes `Broadsheet.Brush.Bg` and `Text.OnAccent` becomes `Broadsheet.Brush.Bg` *as text on accent* — same target, different reasoning. Collapsing them now would destroy that distinction.

**`Application.Current` is `null` in tests.** Any resolution helper that reaches for `Application.Current.Resources` at static-init time will `NullReferenceException` the moment a test touches the type. `FrameworkElement.TryFindResource` on the live element is the safe form and is what is specified.

**Popups live on their own `HwndSource`.** A `Popup`'s child is not in the parent's visual tree. Resource lookup still works because it walks the *logical* tree and terminates at `Application.Resources` — which is precisely why the dictionaries go in `App.xaml`. Putting them in `Window.Resources` would appear to work for most of the UI and fail in the 21 help popups.

**The History tab's gold trio is doomed but not yet.** `#FFF8DC` / `#DAA520` / `#B8860B` (`MainWindow.xaml:1715-1717`) have no Broadsheet counterpart — 3a's tab strip is uniform, differentiated only by a 2 px accent underline. T-001 keys them anyway (pixel-equivalence), with a comment saying T-004 deletes them. Dropping them early would be a visible change in the wrong task.

**The legacy layer's two failure directions are opposite and both silent.** Deleting the dictionaries while references remain leaves the app running with default colours and no error; keeping them after the last reference dies leaves two dead files merged into every launch forever. Assertion 9 is deliberately two-sided for that reason — one branch is the early-deletion guard, the other is the retirement trigger. Neither direction is discoverable by eye in a 2,796-line file.

**Uncommitted working tree.** 11 modified test files and 2 untracked paths are live right now. A `git add -A` would fold someone else's interrupted coverage run into this commit. See DECISION 2.

**`dotnet format` does not see XAML.** CI Gate 1 is Roslyn-only. The `.editorconfig` `[*.xaml]` block (CRLF, UTF-8, 4-space, trimmed trailing whitespace, final newline) is enforced by nothing — honour it by hand or the files will differ in whitespace from every other XAML in the repo.

**A dictionary with `x:Class` would join the coverage conversation.** `Themes/` files must have no code-behind. A generated partial class in `WindowsFileManager.Themes` falls outside `coverlet.runsettings`'s `Include` today, but that is an accident of the filter rather than a guarantee — and `ARCHITECTURE.md:449` is explicit that `Helpers/` is inside `Include`. Keep the dictionaries code-free.

**Serif at 11 px.** DECISION 1's Recommended (b) Cambria exists precisely because of this: `Source Serif 4` at the 11 px this app uses for nearly everything (122 of 231 `FontSize` attributes) is materially harder to read than a face designed for small on-screen sizes. The canvas cannot settle it, because the canvas sets body copy at 15 px. If the product owner overrides to (a), T-003 should expect to raise the chrome sizes or accept the legibility cost, and should say which in its own spec.

## Risks

**1 — Silent `DynamicResource` failure across 393 substitutions.** *High likelihood, medium impact.* A mistyped key produces no error anywhere; the app runs with a wrong-but-plausible default. **Mitigation:** contract test 1 is written *before* the substitution starts, so every batch of replacements is validated by `dotnet test` as it lands. Do not leave it to the end.

**2 — Reviewer fatigue on a ~400-line diff in a 2,796-line file.** *High likelihood, medium impact.* A value drift inside the noise is easy to miss. **Mitigation:** contract test 4's committed key→ARGB map makes value preservation machine-checkable; land the dictionaries in one commit and the substitution in a second so the diffs are separately readable (both still carry their doc updates per the sync rule — the dictionary commit touches no behaviour, the substitution commit touches SPEC-006/010).

**3 — Churn collision with T-002.** *Medium likelihood, medium impact.* T-001 rewrites ~400 lines of `MainWindow.xaml`; T-002 then shreds the file. If both are in flight, the merge is ugly. **Mitigation:** strict sequencing — T-001 lands and is committed before T-002 opens the file. This ordering is also *why* the substitution belongs here: once decomposed, the same work costs a dozen files.

**4 — Scope creep into 4a.** *Medium likelihood, high impact.* Transcribing `styles.css` puts a dark-theme discussion one scroll away, and the Broadsheet accent/accent-2 pair *looks* like a semantic system. Adding `Theme.Dark.xaml` "since we're here" mis-targets the epic. **Mitigation:** only the light `:root` block is transcribed; case 21 in the matrix makes a dark ramp a review rejection; the architecture is *ready* for a theme goal and ships none.

**5 — `color-mix` mis-transcription.** *Medium likelihood, medium impact, invisible until T-005.* Two divider forms with wrong values will not fail anything in T-001 because nothing consumes them. **Mitigation:** contract test 5 asserts the Broadsheet values including both divider forms, with the derivation shown in a comment.

**6 — "Pixel-equivalence" is asserted, not measured.** *Medium likelihood, medium impact.* There is no visual-regression harness and building one is out of scope. The claim rests on value preservation (mechanical) plus a manual screenshot pass (human). **Mitigation:** state this honestly in the commit body rather than implying automated proof; the screenshot pass must cover all three tabs, one open `?` popup, and the `ProfileNameDialog` in its error state — the three places where resource lookup crosses a tree boundary.

**7 — Coverage gate fails for reasons T-001 did not cause.** *Medium likelihood, low impact.* The tree already holds 11 modified test files; ADR-011 records that the *previous* mechanism flaked in 20-40 % of runs (the collector fixed that, but the memory is fresh). A red gate will be blamed on T-001. **Mitigation:** DECISION 2 — establish a green baseline (`dotnet test` + `./scripts/Check-Coverage.ps1`) *before* touching anything, and record the result.

**8 — `FormattedTextBehavior` edit disturbs the help system.** *Low likelihood, medium impact.* It is `[ExcludeFromCodeCoverage]`, so no test exercises the grammar — a regression there is invisible to CI. **Mitigation:** the literal-fallback `??` means the worst case is today's exact colours; the manual pass must open a popup containing `<h>`, `<w>` and the one `<link>` (the `REGEX` popup, SPEC-010 rule 16).

**9 — `po:Freeze` breaks a future animation.** *Low likelihood, low impact.* No animation exists today (verified 0 hits). **Mitigation:** note it in `Broadsheet.Tokens.xaml`'s header comment so the next person animating a brush clones it first.

**10 — Key-naming regret.** *Low likelihood, medium impact.* 76 legacy keys named for observed roles will occasionally read oddly once the surface is rebuilt (`Legacy.Brush.Panel.FolderBorder` is meaningless after T-005). **Mitigation:** these keys are *designed* to be deleted — Interfaces §6 puts the expiry in writing, names **T-011** as its owner, and backs it with assertion 9 so the deletion is triggered mechanically rather than remembered. **11 — The published contract is ignored by a downstream task anyway.** *Was high likelihood — eight of eleven tasks already deviated on their first draft — now low, medium impact.* A convention that lives only in prose gets re-invented by whoever writes the next spec. **Mitigation:** the three most-violated clauses are no longer prose. Key shape (assertion 7), reference kind (assertion 8), folder + merge discipline (assertion 10) and legacy lifetime (assertion 9) fail `dotnet test`, and Interfaces closes with a table of the exact acceptance rows T-002 / T-003 / T-011 must carry, so the obligation is visible from both ends. **12 — Assertion 8's element-type table meets a type it does not know.** *Low likelihood, low impact.* A later task defines a resource of an unlisted type (`BoxShadow`, a `Geometry`, a custom markup extension) and the reference-kind assertion cannot decide. **Mitigation:** unknown types **fail with an explanatory message** rather than defaulting to "allowed" — extending the table is a one-line, deliberate edit, whereas a silent default would quietly hole the rule.

## Open decision

Two forks. **DECISION 1 now carries a Recommended default and a named answerer, so the epic can build with no further human gate; DECISION 2 is the only thing that genuinely blocks the first commit.**

**DECISION 1 — the Broadsheet typeface. Answerer: the product owner (the user who set the 3a target). Recommended: (b) Cambria. Deadline: before T-003 opens; if unanswered by then, T-003 proceeds on (b) without asking again and T-012's ADR records it as the no-answer default. Blocking for nothing in T-001.**
Broadsheet's `styles.css` sets both `--font-heading` and `--font-body` to `"Source Serif 4", system-ui, sans-serif` — a Google-hosted webfont, SIL OFL. WPF has no `@import url(...)`; a custom face must be embedded as a `Resource` and referenced `pack://application:,,,/Fonts/#Source Serif 4`. Three options, all real:
- **(a) Embed Source Serif 4.** Faithful to the canvas. Costs: ~4 font files (Regular/SemiBold/Italic × subset) at ~120-300 KB each committed to the repo and carried into every MSIX build (ADR-008); a `licenses/OFL.txt`; and a legibility risk — Broadsheet sets UI chrome in a serif, and this app's dense chrome runs at 11-13 px where WPF ClearType on a serif at 11 px is materially worse than at the canvas's 15 px body size.
- **(b) Substitute a Windows-shipped serif — Cambria. ★ RECOMMENDED, and the no-answer default.** Cambria ships with every supported Windows (Vista onward, and in the .NET 8 / Win10 22621 target floor this project already sets), was designed specifically for on-screen reading at small sizes, and carries zero repo weight, zero licence file and zero MSIX payload change. It keeps the press-ink texture that makes 3a read as Broadsheet while retiring the one risk — serif legibility at 11 px — that (a) cannot mitigate. It is chosen over (a) because the canvas's fidelity argument is about *character*, and Cambria delivers the character at the sizes this app actually renders; it is chosen over (c) because turn 3 says plainly *"the typography, colors and controls stay Broadsheet"* — dropping the serif altogether would silently re-target the epic.
- **(c) Keep the system UI face** (Segoe UI, today's effective default — `MainWindow.xaml` declares no `FontFamily` except `Consolas` ×5 and one explicit `Segoe UI` at `:1120`) and treat "Broadsheet" as a colour/space/rule system only.
**T-001 is unblocked under all three**: it writes `Broadsheet.FontFamily.Heading` / `.Body` / `.Mono` as keys and sets them to the *current* effective faces (`Segoe UI` / `Segoe UI` / `Consolas`) so pixel-equivalence holds, each with an XML comment naming the canvas value, the recommendation, and the deadline. Flipping the chosen face is a two-line edit in one file. Under `--auto-approve` the Recommended option is taken immediately and logged, per root `CLAUDE.md` § The `--auto-approve` flag clause 3.

**DECISION 2 — the uncommitted working tree. Answerer: the user. Blocking: yes, before T-001's first commit.**
`git status --short` on `main` right now shows **11 modified test files and 2 untracked paths** (`tests/.../Helpers/FormattedTextBehaviorTests.cs`, `tests/.../ViewModels/`) — an interrupted coverage run from a closed session. T-001 adds a file to that same `tests/` tree and must land a green `dotnet test` + `./scripts/Check-Coverage.ps1`, so it cannot ignore them. Pick: **(a) ★ recommended — commit that batch first as its own commit** (then T-001 starts from a clean tree; the batch appears intact and coverage-motivated), **(b)** stash it and let T-001 land against the last commit `9054406`, or **(c)** T-001 commits only its own paths with an explicit pathspec (`git commit -m … -- src/WindowsFileManager/Themes src/WindowsFileManager/App.xaml … tests/…/Themes/DesignTokenContractTests.cs docs/`), leaving the batch dirty — which risks the coverage gate failing for reasons T-001 did not cause. **Do not silently `git add -A`.**

Everything else in this task is decided below and needs no user input — including the resource-key naming scheme and its reserved `Broadsheet.Style.*` namespace, the `DynamicResource`/`StaticResource` rule (now normative and machine-enforced, not a review convention), the legacy layer's named retirement owner, and the deliberate exclusion of the `FontSize`/`Margin`/`Padding` substitution.
