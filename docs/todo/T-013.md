## Concept

`docs/README.md:40` currently states, as a fact about this repository, that there is no `docs/design/` because "the features were built before the spec layer was reverse-engineered from the code, so there is no design-time snapshot to preserve." That sentence was true on 2026-08-30. It stops being true the moment this epic starts, because the epic *has* a design-time snapshot: a multi-artboard design canvas that explored eleven framings of the app across four turns, of which option **3a** — IDE-standard tool-window framing in the Broadsheet design system — was chosen as the build target.

Right now that snapshot exists in exactly one place: `C:\Users\priva\Downloads\UI mockups project planning\`. A user's Downloads folder, on one machine, holding the sole copy of the requirement that eleven other tasks build against. T-013 moves it into the repository as a **frozen design-time record**, gives it the home the repo's own documentation standard already reserves for it, writes the design record that says *3a is adopted, 4a is explored-and-deferred, and here is the transcribed inventory of what 3a actually specifies* — and then repairs every one of the six places in the doc set that enumerate "four kinds" or assert the absence of a fifth.

This is the cheapest task in the epic and the one whose absence hurts most: without it, every other task cites a path outside the repo, `T-001` extracts design tokens from a file no reviewer can open, `T-012`'s ADR has no evidence to cite, and the first thing a new contributor reads about the doc set is a sentence that contradicts the folder sitting next to it.

**Three ideas carry the design.**

**1. The design kind is *frozen*, and frozen means never re-synced.** The repo already has one frozen kind (ADR: "frozen at acceptance; superseded, never rewritten") and three living ones. A design doc joins the frozen side, but for a different reason than an ADR: an ADR freezes *why we chose*, a design doc freezes *what we intended before we built*. Its value is precisely that it does **not** track the code — when the shipped frame diverges from 3a, the divergence is visible only because the design stayed still. This has to be stated loudly in `_index.md`, because T-001…T-011 will each be tempted to "update the design doc", and **T-014 (perfect-docs) is a terminal doc-sync pass whose whole job is making docs match what shipped** — it must be told, in writing, that `docs/design/` is out of its sync surface.

**2. DESIGN-001 is a transcription, not a summary.** Its centre is a geometry inventory read out of the artboard markup — pixel heights, the literal `grid-template-columns`, control classes, the exact strings. This matters more than it sounds: **the epic brief's paraphrase of 3a diverges from the markup in five verifiable places** (splitter count, group-vs-copy verb placement, the Rules panel's two-row header, the compose-row control order, and the results toolbar being a 36px row plus a separate 26px column-header strip). A downstream task built from the paraphrase builds the wrong thing. Once DESIGN-001 exists, "the canvas is authoritative; read DESIGN-001 § Inventory" is a one-line answer instead of a re-derivation, and each divergence is recorded so nobody re-discovers it a third time.

**3. Vendoring 4a's markup is not scoping 4a in.** The `redesign-explorations.dc.html` file contains all eleven artboards including 4a (light/dark theme switch, cyan/magenta/print-yellow colour-as-meaning, tinted rows and file-type tags). It ships whole — an exploration record with the rejected options cut out is a worse record. DESIGN-001 therefore carries a **status column per artboard**: 3a `Adopted`, 4a `Explored — deferred, follow-on goal`, everything else `Explored — not adopted`. The status column is what makes the file safe to commit: it is the difference between "here is a menu" and "here is the order". Any task that cites 4a as a requirement is mis-targeted, and DESIGN-001 says so in a sentence.

**Sequencing.** This task has zero upstream dependencies and unblocks four others, so it runs first despite its number — see `## Dependencies`.

## 3. Byte-fidelity: `core.autocrlf` and `.editorconfig` will both corrupt this if left alone

Two verified facts collide with "frozen":

- `git config core.autocrlf` → **`true`** in this repo, and **no `.gitattributes` exists**. Every vendored file is LF. With `autocrlf=true` git normalises LF→LF in the index but checks out **CRLF in the working tree** for anything it sniffs as text — so a fresh clone's `styles.css` no longer hashes to `03741248…`, and the provenance manifest becomes unverifiable on the very first clone.
- `.editorconfig` `[*]` (lines 3–9) sets `end_of_line = crlf`, `insert_final_newline = true`, `trim_trailing_whitespace = true` — applied to *all* files. Three vendored files end **without** a final newline. Any editor or agent that "tidies" the folder mutates a frozen artifact.

**Cure — create `.gitattributes` at repo root:**

```gitattributes
# The frozen design canvas is a byte-exact vendored artifact; its recorded
# SHA-256 digests (docs/design/DESIGN-001-ide-frame-redesign.md § Provenance)
# must reproduce on any clone. No EOL conversion, no diff/merge munging.
docs/design/canvas/** -text
docs/design/canvas/**/*.png binary
docs/design/canvas/.thumbnail binary
```

**Cure — append to `.editorconfig`** (after the existing `[*.json]` block, so it wins by later-match precedence):

```editorconfig
# Frozen vendored design canvas — never reformat. See docs/design/_index.md.
[docs/design/canvas/**]
end_of_line = unset
insert_final_newline = false
trim_trailing_whitespace = false
indent_style = unset
indent_size = unset
charset = unset
```

Note `charset = unset`: `.thumbnail` and `app-icon.png` are binary and the `[*] charset = utf-8` rule has no business claiming them.

## Open decision

Two real forks. Both change what lands on disk, neither can be settled from the repo alone.

---

**FORK 1 — What fidelity of the canvas gets vendored?**

The canvas is **not a static document**. Verified: both `.dc.html` files load `./support.js` (69,150 bytes), which pulls React 18.3.1, ReactDOM 18.3.1 and Babel standalone 7.29.0 from `unpkg.com` at open time; `_ds/…/styles.css` `@import`s Source Serif 4 from `fonts.googleapis.com`; the doc head links Phosphor icons from `unpkg.com`. The 3a artboard's result rows are a runtime repeat — `<sc-for list="{{ groups }}" as="g" hint-placeholder-count="3">`. **Opened with no network, 3a renders as unstyled markup with a literal `{{ groups }}` in the results area.**

| | Option | Size added | Reads offline? | Cost |
|---|---|---|---|---|
| **A** | Vendor the runnable bundle only (10 files, 343,869 bytes) | +343.9 KB (+26% of the 1,324,623 bytes currently tracked) | ✗ — needs unpkg + Google Fonts | A "frozen artifact" that a future reader on a locked-down machine cannot read at all |
| **B** ★ | Bundle **plus** a committed static export of the adopted artboard — `docs/design/canvas/exports/3a-ide-duplicates-1600x900.png` (and optionally `baseline-main-window.png`) | +~400–600 KB | ✓ the PNG always; the live canvas when online | One extra manual export step at seed time (the canvas editor's export, or a headless-Chrome screenshot of the `#3a` card at 1600×900) |
| **C** | The two `.dc.html` files alone | +186.4 KB | ✗ — renders as broken markup | Cheapest and worst: the artifact does not render at all, not even online |

**Recommended: B.** The whole point of `docs/design/` is that the intent survives — surviving means legible in five years with unpkg gone. The PNG is the durable read; the bundle is the inspectable source. Cost is one export action.

**The user must settle:** B as described, or A (accept network-dependence), or C. *If nobody answers, build A and open a follow-on for the export — do not silently skip the fidelity note in DESIGN-001.*

---

**FORK 2 — Does the Broadsheet `_ds/` slice ship as-is, with its dangling internal references?**

The vendored `_ds/broadsheet-20e204aa-d8f4-4c1f-9771-d781d63fcc9d/` holds 5 files. Its own `readme.md` and `_ds_manifest.json` reference `components/buttons.html`, `components/forms.html`, `components/table.html`, `templates/`, `theme.json` and `print-plates.js` — **none of which exist in the copy**. The docs portal's standing promise is that every referenced file exists on disk.

- **(a) ★ Vendor as-is, add a caveat** in `docs/design/_index.md`: "the `_ds/` slice is the exported subset the canvas actually loads; its `readme.md` and `_ds_manifest.json` are the design system's own files and reference component pages that were not exported. Do not chase those links; do not edit these files."
- **(b)** Prune `readme.md` / `_ds_manifest.json` down to the shipped slice — **rejected in the recommendation**: it edits a frozen third-party artifact and destroys byte-fidelity against the source hashes.
- **(c)** Vendor only `styles.css` — loses `readme.md`, which carries the *"take every color, font, spacing, radius and shadow from its variables … never hard-code a hex"* rule that is literally T-001's motivation and the reason 70 hardcoded hexes are a defect.

**Recommended: (a).** Keep the frozen thing frozen; put the caveat in the index where a reader meets it first.
